Import and export sessions deferred to Sprint 06 as session-oriented work. |

Verifying against the real client contract found that zero-argument abilities were uncallable through the run endpoint because a client that omits input sends null; schemas now allow null. Import composites were deliberately not built: the mapping step depends on the importer type, and four honest primitives beat a composite that guesses. |

| [08](../sprints/sprint-08-vector-spaces.md) | Gates 1–3 green: 63 abilities, 460 tests / 5029 assertions, live smoke 9/9 | Vector spaces landed: a registry table plus one physical table per space, built for the dimension supplied, so arbitrary embedding sizes work. | [09](../sprints/sprint-09-embedding-providers.md) | Gates 1–3 green: 64 abilities, 468 tests / 5060 assertions, live secret check | Embedding providers landed behind one contract, with an OpenAI-compatible base class so OpenAI and Ollama share a path and a self-hosted gateway needs configuration rather than code. | [10](../sprints/sprint-10-indexing-pipeline.md) | Gates 1–3 green: 66 abilities, 477 tests / 5112 assertions, live smoke 6/6 | Chunking and indexing landed: save-time enqueue instead of inline embedding, chunk hashes so unchanged content costs nothing, and immediate vector removal on unpublish, trash and delete. The smoke measured the point of the sprint — a second run of an unchanged item embedded 0 of 3 chunks. Item metadata values are not chunked yet, recorded as a gap rather than quietly omitted, because the read API is a different shape and Sprint 12 can prove whether the omission hurts. |
| [11](../sprints/sprint-11-resilience.md) | Gates 1–2 green: 68 abilities, 482 tests / 5158 assertions, live smoke 7/7 | Backfill and resilience landed. The cursor is the highest queued item ID rather than an offset, because an offset walks a list that shifts under an import. The circuit breaker pauses a provider+model pair after three consecutive failures and stops the whole run, since row-level backoff cannot help when the provider itself is down. A test caught that a full final batch reported `running` and forced a pointless extra poll; `step()` now checks whether anything remains beyond the cursor. |
| [12](../sprints/sprint-12-retrieval.md) | Gates 1–3 green: 70 abilities, 494 tests / 5202 assertions, live smoke 16/16 | Retrieval landed with the filter in the only place it can work: candidates from the space table, then the candidate IDs re-fetched through the `Items` repository, then the count of what was dropped reported as `filtered_out`. Found a scoping defect from Sprint 10: `Indexer` wrote the space id into `collection_id`, so a per-collection filter matched everything; vectors indexed before the fix need rebuilding. Also measured what had been assumed — MariaDB 11.8.9 filesorts every `ORDER BY VEC_DISTANCE_COSINE(...) LIMIT n` shape tried, even with `FORCE INDEX`, so retrieval is a bounded scan, not an ANN scan. The index can be created; it is not being used. |
| [13](../sprints/sprint-13-admin-console.md) | Gates 1–3 green: 72 abilities, 501 tests / 5253 assertions, live smoke 18/18 | The console landed as one server-rendered page over `Rag\Status`, with every button pressing the callback its ability is registered with, so the human and agent surfaces cannot drift. `rag-status` reports a space whose table was dropped instead of emitting database errors, and `has_index` is `null` rather than `false` because "no index" and "no table" are different problems. Queue recovery arrived with `retry_failed()`, which keeps the attempt counter so a requeued row still backs off honestly and pressing twice invents no work. The preview prints candidates scanned and candidates dropped, which is the number that separates "nothing matched" from "matches were hidden". |
| [14](../sprints/sprint-14-hybrid-and-answers.md) | Gates 1–3 green: 74 abilities, 516 tests / 5308 assertions, live smoke 22/22 | Hybrid search fuses keyword and vector results by reciprocal rank, because cosine similarity and a keyword order have no common unit and adding them is a fiction. Keyword is the fallback rather than the exception: every vector-side failure degrades and names its reason. `rag-answer` returns citations built from what retrieval actually returned to the caller — so never a document they could not open — and with no generator wired it returns `reason: no_generator` plus the prompt instead of inventing prose. Reordering `Search_Engine` output is opt-in and page-local: it changes order, never page membership, so pagination stays WordPress's. Opening the console in a browser then changed four things tests had not: deleted spaces take their queue rows with them; the preview's collection field became a select of names; the provider list became the site's WordPress AI connectors rather than vendor entries with their own keys; and the model field is now read from the chosen connector, falling back to free text only when that connector advertises no embedding model. |
